## 2. 決定
- D-02a **主張の候補を④に置く（ChatGPT と合意）。** 「この模型では、保持の規則によって、誤った答えに記憶と場面の不一致が伴う場合と、名前の忘却によって不一致が検出されなくなる場合が分かれた」。構造写像の優位性は主張しない。
- D-02b **「誤りの印も消えた」は使わない。** 「調べた指標が誤りを見分けられなくなった」と言う。支持が満点になるのは、U を分母から外す点数の作りからも説明できると明記する。
- D-02c **「局所的な忘却が全体として損」は候補から外す。** F の記憶の少なさは、F の作りの副作用（定義が手放されない）と混ざっている。
- D-02d **F は原因の確かめにだけ使い、記憶の量の比べには使わない。** 再び使うなら、「守った席は、他の席が全部 U の定義を手放すのを妨げない」に直す。
- D-02e **外れの分類は二つの軸。** 原因（選び間違い → 区別の喪失 → その他の順）と、答えの出どころ（F・H・U の既定値）。判定は予測の時点の今の席の中身で行い、生まれた型は参考の列に残す（アストラ承認）。
- D-02f **LLM は Claude Haiku 4.5（推論あり）で進める。**
  - メモの上限の格子：超えたら一度書かせて先頭だけ残す（主）。上限 150 だけ一度書き直させる（比べ）。
  - 指示に「課題の説明は毎回与えられる」「持ち越すのは保存したメモだけ」「超えたら先頭だけ保存」を足す。
  - 全履歴で解ける条件を探す段階は、元から一項目ずつ変え、全段階を記録する。採用したら新しい記号の組で確かめる。
- D-02g **集団化の方針（アストラ）。**
  - 問いは、空間的な支配と協調ゲインの両方。
  - 個体の忘れ方は C と D の両方。
  - 伝える確率・混ざる割合・f を振る。
  - アストラは LLM の集団化まで強く望んでいる。
- D-02h **Mac の上の重い処理は、Codex と Mac の Claude Code を合わせて並列 4 まで。** 委任書には、始める前に機械の余裕を確かめる段を入れる。
- D-02i **一階を散らした本番の世界は後回し。** 構造写像の能力を確かめるなら、「名前は同じで、役割のつながりだけで答えが変わる」小さな検査にとどめる（ChatGPT）。

## 5. 教訓
- アストラは添付を読まない。前提から、主語と理由を省かずに、具体的な例で、一つずつ説明する。
- 質疑の形（小さな問いを一つずつ）は、アストラの理解に最も効いた。地図を浅く一周したので、次は一つの試行を実際の記録で深く追う。
- 委任書を出す前に、同じ機械で何が動いているかを確かめる。
- 予想を確かめる前に、作った道具の中身（記憶の中身）を見て、作りが意図どおりかを確かめる。
- 「結果が作りから予想できること」と「問いの価値」を混ぜて伝えない。
