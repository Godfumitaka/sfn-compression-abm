**D-36 取り込みは「足さない」を主とする（--extend-rule none）**
- 理由：足す版（v3.1a）は、足す行の番号を定義の側に読み替える所が壊れていて、一度もまともに動いていなかった（§4 の誤り1）。足さない版は中心的過程が「引くだけ」になり、理論（共通項を取って厚みがなくなる）に素直。足さない版の弱点（薄い定義が場面を吸い込み、誕生が止まる）は、両側で照らす同化（D-37）で消える。アストラの「新しい定義として生まれればよい」がそのまま実現する。
- 足す版は、番号の読み替えを直してから、比べとして走らせる（仮U-8）。
- 決められなかったことの記録：足す・足さないには、どちらにも支持がある（足す＝SAGE の向き、足さない＝SEQL 寄りの第三の形）。理論の決め手ではなく、壊れていること・時間・理論への素直さで主を決めた。

**D-37 同化先の決め方を変える（旗 A・B・C）**
- A（--ident-rho ρ）：似ている度合いを両側で測る。比＝点(定義, 相手) ÷（点(定義, 定義) ＋ ρ × 相手の側だけの点）。ρ＝0 で今と同じ。主は ρ＝0.5。
- B（--ident-argmax）：最初に基準に届いた定義ではなく、一番高い定義を選ぶ。同点は今の走査順（同化の回数の多い順、新しい順）。
- C（--ident-commons）：照らす相手を、いまの場面全体ではなく共通構造にする。作り方は C1。
- C1 の理由（アストラ）：「cause(push, X) と cause(push, move) を見たら、cause(push, X) という型がこの世界にあると推論する。X の枠は slot_history で縛られる」。スキーマ（枠のある知識の型）の考え方。加えて、世界の作りが「結ぶ相手の片方が違う高階の関係」（govern など）も共通と数えていること、伏せ辺の親が毎試行落ちる偏りを避けること。
- ρ の値に決め手は無い。掃引軸とする（0・0.25・0.5・1.0）。ρ＝0 は丸め込みの極端な端として残す。
- 理論の足場：Tversky（1977）の比の式で、今の NSIM は「相手の側だけの特徴への重みを 0 にした」端。仮説の条件を主に確かめる傾向（Klayman & Ha 1987）。

**仮C-1 誤りは、見たことのない型の場面に集中する（どの版でも）**

| 版（hide） | 見た・話した | 見た・話していない | 見ていない |
|---|---:|---:|---:|
| v2（s21） | 2.9% | 2.7% | 39.5% |
| v3・0.8 | 0.7% | 4.9% | 50.1% |
| v3.1a・0.8 | 1.6% | 11.5% | 61.9% |
| v3.1b・0.8 | 2.4% | 35.8% | 79.3% |

**仮C-2 その差は、フィードバックが作ったものではない**
- f=0 でも差はすでにある。種ごとの中央で f=0 → f=1.0：v2（s21）は話した型 4.2% → 2.2%（18/20種で下がる）、見ていない型 46.7% → 39.0%（17/20種）。v3.1a・b では f の効き目はほとんど見えない。
- 見ていない型の誤りは、f=1.0 でも大半が残る。
- 読み方：分けているのは「フィードバックが届いたか」ではなく「見ていない世界に外挿したとき当たるか」（覚書 §3 の問いの形）。水位説は「フィードバックを最大にしても、見ていない世界の誤りの大半は内側から直らない」の形で支持。

**仮C-3 D-32 は正しく動いていた**

**仮C-4 世界の作り**
- 各モチーフの構造の関係は15本、述語の異なりは30。30本すべてが、ちょうど二つのモチーフに、同じ位置で出る。
- 部分木 T1〜T4 がモチーフの組に共有される：M1–M2 は T1 と一番上の govern（8本）、M3–M4 は T4 と sustainedby（8本）、M1–M3 は T2（7本）、M2–M4 は T3（7本）、M1–M4 と M2–M3 は 0。

**仮C-5 話す定義の選び方（U-25 の答え）**
- 支持比（写った生きている行の本数 ÷ 生きている行の数）が最大の一本。同点は m_live の大きい方 → 新しい方 → 名前の辞書順（台帳一本で辞書順まで行ったのは 0 回）。選んだ一本だけを門 ⌈0.67·m_live⌉ にかけ、届かなければ棄権。
- 薄い定義ほど話しやすい。薄い定義は生きている行が全部写るので投影の先が無く、墓石の穴埋めで話す。

**仮C-6 同化先の決め方（直す前）**
- 候補は m_live > 0 の定義。同化した回数の多い順・新しい順に見て、最初に基準に届いた定義を採る（仕様どおり）。人気の定義がますます人気になる。
- 点の式：4×対の数 ＋ 1×引数の対応の数 ＋ 2×体系性 − 0.25×定義の側で対にならなかった行の数。NSIM ＝ 点(定義, 場面) ÷ 点(定義, 定義)。場面の側だけの行は点に入らない。
- 試しの数で、「少数の薄い定義が全部を吸い込む」状態を作っていた主な原因は ρ＝0（片側だけで照らすこと）。B と C はほとんど効いていない（ρ だけ 0 の腕は誕生 18〜30、今の同化は 4〜10、新しい同化は数百）。

**仮C-7 走行時間の 97% は記録**

- --fast で 704 → 305秒（1バイトも同じ）、--no-public-history で 295秒、両方で 184秒（約3.8倍）。public_history を除いた指紋は全 1,740 試行で一致。解析の道具は public_history を読んでいない（9/10 の古い道具3本だけが読む）。

**仮C-8 機械による台帳の違い**
- クラウド（x86・glibc 2.39・uv の 3.12.13）とデスクトップ（WSL x86・同じ Python）は一致。
- マック（arm64・Homebrew の 3.12.13）は、seed002・θ′2.1 で試行 1288 から分かれる。v3 では試行 1361 から（ell_frozen の 1 ULP）。原因は突き止めていない（機械と数学ライブラリの違いと見ている）。

**仮C-9 名前の順番の直しの確かめ**
- 直す前：述語の名前を付け替えると、同化の判断 1,739 回のうち 960 回（55%）が変わった。
- --fix-order（一回目の直し）：28・23 回。--fix-order2（案1）：述語名・ID・関係の並び・定義の並びのどれを付け替えても 0 回（台帳一本の全試行、同化の判断・話す定義・予測）。
- 答え合わせ（全部の組み合わせを探した最良の付け方と比べる）：同化の判断に使う突き合わせ 1,179,907 回はすべて一致。場面どうし 1,500 組では 23 組（1.5%）が、最良の付け方が二通り以上ある組で、対一本分（6.25点）を落とした。重さは 4.5% 増。

**仮C-10 直し②を会計に広げると、生まれる定義が減る（誤りが直った結果）**
- 基準 0.7・seed001・θ′2.1・最頻で、旗を一つずつ変えた：直し②を選ぶ所だけ（v3.2-main の旗）で走行末 375本、会計にも広げると 82本。投影の優先と案1は数に効かない。どの版でも丸ごと消えた定義は 0 本で、差はすべて生まれる数。同化は 1,363 → 1,656 回に増える。
- 理由：前は、墓石を子に持つ親の行が、子の見える場面で「判定不能」とされて不当に死に、定義が不自然に痩せていた。痩せた定義は場面を覆えず、新しい定義が次々に生まれていた。直すと行が死ににくくなり（判定不能 5.1% → 0.2%、② 3.9% → 1.8%、行の死は1本あたり中央 5 → 3本）、定義が場面を引き受けられる。
