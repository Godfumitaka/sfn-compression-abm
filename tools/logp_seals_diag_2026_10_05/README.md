# 保存記録による腕Lのシール・記憶量診断

`SPEC.md` を先に読む。模型・照合・既存の分類の関数は編集しない。対象は `stage1.ARMS` の五条件、種1〜20だけ。全件の入力パスは公開フォルダの `inventory.csv` と `input_sha256.csv` にある。模型の再走行はこの診断に含めない。

実行した順序と受付枠は `commands.json` に残す。各処理は `~/jobs/jobs.py run --wait --mem --disk-path` に通す。`stage1.py` が停止条件を検査し、その関門を通過した場合だけ `priority.py`、`stage2.py`、`silent_candidates.py`、`aggregate.py` を実行する。最後の処理は前二者の完了ファイルが必要である。

独立診断の保存先は作業枝の `tools/logp_seals_diag_2026_10_05/`。この保存された版を直接使う場合は、環境変数 `LOGP_SEAL_WORKSPACE` に実際の診断の作業場所を渡す。そこにある入力由来の中間記録も読むので、作業場所の指定は必須とする。実走行で使用したファイルと保存版の指紋一致は `diagnostic_code_sha256.csv` に残す。

初回の欄確認 `inspect_records.py` と報告保存用の補助は、実行時の作業場所から使う版をそのまま保存している。これらを使う場合は作業場所へ写して実行する。主要な段1・段2の診断は前段落の環境変数による指定を使える。

`silent_candidates.py` は既存の `selcands.one` に予測前の凍結記憶を渡し、元の黙りを再現したうえで候補の答えを数える。既存の読込手順が静的な場面の識別子を再構成するが、学習の走行、記憶更新、忘却、模型の台帳の出力は行わない。研究者が与える日・ドアの正解は解析のラベルだけに使う。

`stage2.py` は500/1000/1500/1740試行の費用を保存された状態から数える。strict-pcの関係引数の符号化を診断内の算術で復元し、総ビット・定義数・F/H/U数を記録のsideと全件照合する。定義の名前による通常/例外分類と出生材料による分類は別の欄にする。

`aggregate.py` は3060件の例外ドア、9518件の誕生、400件の記憶時点を統合する。選び間違いと区別の喪失、候補結果の一意な対応、最後の100時点と先行表の一致を検算する。外れ数そのものの大小を関門には使わない。関門は既報・元の記録との一致である。
