## --v39-init zero で定義が生まれなかった理由（コードの事実）
- 定義は毎試行生まれている（side の誕生の記録は種 1 で 1,739 件）。ただし、同じ試行の削除の段で全部の席が U になり、定義ごと退役する。
  - side の v39 の行では、試行の終わりの定義の数がどの試行でも 0。
  - 種 1・試行 1 の例：生まれた定義 R_f35c… の 4 席が、F→H→U の順にすべて "price" で変換され、退役した。
- 順を追うと：
  1. tools/v39.py:773-774 _init_rec：--v39-init zero のとき、新しい席の点数の記録を SeatRec(0, "F", trial, trial, ZERO4, ZERO4) にする（初期分も誕生後の分も 0）。
  2. tools/v310be.py:183 candidates：R̄F・R̄H・R̄U を rec_means（tools/v39.py:207-217）で読む。全部 0 なので、分子は FH なら R̄H−R̄F＝0（:187）、HU なら R̄U−R̄H＝0（:193）。V＝0／ΔC＝0（:198）。
  3. tools/v39.py:906・911 run_conversions：λ＝--v39-price（0.0187）＞0 のとき、V＜λ の候補を尽きるまで変換する。V＝0＜λ なので、生まれたばかりの全部の席が変換の対象になる。
     - 一つ変換するたびに候補を作り直す（:961 付近）ので、F→H→U まで同じ試行の中で進む。
  4. 全部の席が U になると、定義は退役する（tools/v39.py _retire_if_all_U）。
- 誕生の試行の削除の段は、誕生（m1）のあとに走る（abm/loop.py:106-119）。そのため、生まれた定義は次の試行の予測に一度も使われない。

## 誕生の初期の成績を外す方法の案（★ 案だけ。走らせていない）
- 案 1（採点が無い席は判断しない）：
  - tools/v310be.py candidates で、席の記録の重み n（rec_means の 4 つ目、採点の重みの和）が 0 の席を変換の候補にしない（--v39-init zero のときだけ効く新しい旗）。
  - 初期の成績は 0 のまま。B の判断は、その席が初めて採点された（開示を受けた答えで点が付いた）あとから始まる。
  - 模型の決まり（V＜λ で薄くする）はそのまま。「証拠の無い席は値段の比べをしない」を足すだけ。
  - 注意：一度も採点されない席は薄くならない（ずっと F のまま記憶に残る）。記憶のビットが増える見込み。
- 案 2（誕生の試行の判断を一つ遅らせる）：
  - 誕生の試行の削除の段では、その試行に生まれた席を変換しない。D の --use-forget と同じ扱い（tools/useforget.py の born の確かめ）。
  - それだけでは、次の試行でも V＝0＜λ なので同じことが起きる（採点が付くまでは 0 のまま）。案 1 と組み合わせる必要がある。
- 案 3（中立の初期値）：
  - 初期の成績を、F・H・U で同じ値（例：書き直し費用を 0 とした 1 回分）にする。
  - 分子は 0 のままなので V＝0＜λ となり、案 1 なしでは同じく全部が薄くなる。λ＝0 のときだけ意味がある。
- 比べると：案 1 が、初期の成績の決まり（今の "two"：二場面で三方式を採点する決まり）を外しつつ、定義が生まれてすぐ消えることを避ける最小の変更。
  - 実装するなら旗で切り替え、旗を切れば今と一字一句同じにする。
