### コード用：H/sfn/sfn-compression-abmの履歴を共有するworktree

担当ごとに開始コミットSHAと未使用の枝名・パスを指定し、原本の作業ツリーをコピーせず、Gitのworktreeを作る。未追跡のrunsや保存状態はコピーされない。Wの外側のGitによる二重保存を避けるため、新規場所はWの外（例：H/sfn-worktrees）とする。Gitオブジェクトは共通、HEAD・index・作業ファイルは担当別になる。[git-worktree](https://git-scm.com/docs/git-worktree)

```sh
# 値はアストラが指定。実施するのは新規担当だけ。
TASK_SOURCE='/Users/tatsu-admin/sfn/sfn-compression-abm'
TASK_WORK='/Users/tatsu-admin/sfn-worktrees/<セッション名>'
TASK_BRANCH='codex/<セッション名>'
TASK_BASE='<指定された開始コミットSHA>'
git -C "$TASK_SOURCE" worktree list --porcelain
git -C "$TASK_SOURCE" worktree add -b "$TASK_BRANCH" "$TASK_WORK" "$TASK_BASE"
git -C "$TASK_WORK" rev-parse HEAD
git -C "$TASK_WORK" rev-parse --git-common-dir
```

同じ枝を複数の作業場所で使わない。原本のcheckout・reset・cleanは不要。出力はGitの作業場所の外の担当別の場所（例：H/sfn-run-outputs/<セッション名>）に書き、実行前のclaimにはその出力先を渡す。保存状態を軽くする変更や古い走行出力の削除はこの手順に含めない。

### 報告用：control/だけを展開する部分clone

GitHubから別の新規場所へpartial cloneし、checkout前にcontrol/のsparse指定を入れる。`--filter=blob:none`は必要になるまでファイル内容を取得しないので、最初から全結果ファイルを展開するcloneを避けられる。sparseだけでは履歴全体のblob量を減らせないため、両者を組み合わせる。[git-clone](https://git-scm.com/docs/git-clone)、[git-sparse-checkout](https://git-scm.com/docs/git-sparse-checkout)

```sh
TASK_REPORT='/Users/tatsu-admin/sfn-reports/<セッション名>'
git clone --filter=blob:none --no-checkout --single-branch \
  --branch results-2026-09-27 \
  https://github.com/Godfumitaka/sfn-compression-abm.git "$TASK_REPORT"
# control/のみを厳密に展開するため、単一の先頭固定パターンを指定。
git -C "$TASK_REPORT" sparse-checkout set --no-cone '/control/'
git -C "$TASK_REPORT" checkout results-2026-09-27
git -C "$TASK_REPORT" sparse-checkout list
git -C "$TASK_REPORT" config --get remote.origin.partialclonefilter
```

Git公式はconeを推奨する。root直下のファイルも含める運用なら`git sparse-checkout set --cone control`を選ぶ。上の案はcontrol/だけを厳密に展開するため、非coneの単一パターンを使う。`--filter=blob:none`だけで全体をcheckoutすると、その時点の全ファイル内容を取得するので、報告用途ではsparseと組み合わせる。走行の出力を成果として公開する担当は、必要な成果パスをその担当の新規報告場所で明示して追加する。既存の成果フォルダー全体を複製しない。
