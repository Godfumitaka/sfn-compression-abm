## 試験の仕組み

- 試験の場面：走行の初めに作って固定する。
  - 作り方：世界とは別の流れ（run_seed の代わりに "probe‖run_seed"）で abm.world.generate_trial（その腕の世界の旗を含む）を呼ぶ。
  - 四つの型それぞれ一場面。その流れで試行の番号 0, 1, … を順に見て、型ごとに最初のものを使う。
- 問い：その場面の骨組みの関係（型の展開の経路 tree:<経路> の関係。一階・高階）を、一本ずつ伏せたもの。
  - 見えている部分と物は、今の世界の作り方と同じ。
  - この種ファイルでは一場面 15 問、四つの型で 60 問。
- 時点：試行 t−1 の終わり（削除の段のあと）の状態で答えさせる。t＝100, 200, …, 1,700 の 17 回と、走行の終わり（t＝1,740）の計 18 回。
- 答え方：その腕の旗のとおりの予測（照合・門・選び方・候補ごとの棄権・U の扱い）。予測の乱数は別の流れ（sha256("probe"‖種‖時点‖問い)）。
- 学習しない。
  - 記憶・履歴・成績・全体の頻度・逐語の記憶を変えない。採点も届けない。
  - 試験の前後で状態の指紋（状態の repr の sha256）を毎回比べ、違えば止める。
  - 部品の数え（STATS・CTX など）も、試験の前の値に戻す。

## 記録（side/<セル>/seed<種>.probe.jsonl、問いごとに一行）

| 欄 | 中身 |

| answer・args／abstain | 答え（述語・引数）、又は棄権の理由 |

| exp_path_n・exp_path_names・exp_path_last | 経験（研究者が、その時点の前までの世界の歴史から数える）。同じ型の場面の同じ経路の関係について、次を数える。<br>・中身を見た回数（見えていた、又は伏せられて開示された）。<br>・名ごとの回数。<br>・最後に見た名。 |

| defs・C | その時点の定義の数と、記憶のビット C（tools/v39.py total_bits） |

- ★ 仕様に無い点：「外挿の印の道具と同じ粗い・細かい状況の鍵」の定義が、マックの道具（routing-2026-09-30 の tools/routelog.py・extrap_reader.py）にも control/ にも見つからなかった。
  - そのため、鍵そのものは作らず、鍵の材料（型・経路・階・親の述語と位置）を記録した。
  - 経験と逐語の記憶は、世界の骨組みの位置そのもの（同じ型の同じ経路）で数え、粗い読み（親の述語と位置）も並べた。
  - 鍵の定義があれば、材料から作り直せます。
