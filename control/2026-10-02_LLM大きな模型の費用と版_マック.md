## 1. 費用の見積もり（Sonnet 5.5・effort medium で、全履歴の五つの段階を走らせた場合）

### 先に一点：「合計 14.46 ドル」について

- 14.462 ドルは、新5 の最後の問い合わせの時点の費用の帳簿（~/llm_trial_out/費用.jsonl）全体の合計。それより前の作業（第一段・理解検査・格子など）を含む。
- 全履歴の五つの段階（新1〜新5）だけを足すと 7.376 ドル。
- 下の見積もりは、この五つ（7.376 ドル）を元にした。

### 元にした数（Haiku 4.5、五つの段階、問い合わせ 360 回）

- 入力・出力のトークン数は、費用の帳簿の in・out の和。段階ごとの記録（llm_trial/全履歴の段階/*.jsonl）の使用量の和と一致した。
- 出力のうち推論の量は、API の応答の使用量にある output_tokens_details.thinking_tokens（推論のトークン数）を使った。
  - これまで報告に書いた「出力 − 本文」の見積もりとは、五つの段階の和で 0.25% 違う（thinking_tokens 767,454 対 見積もり 769,392）。
- 本文は、出力 − thinking_tokens。

### 前提（全部）

1. 値段：Sonnet 5.5 は入力 2 ドル・出力 10 ドル（100 万トークンあたり。推論も出力として数える）。
   - platform.claude.com/docs/en/about-claude/pricing、10-02 12:58 に確かめた。
2. 問い合わせの回数と中身（場面・指示・問い）は、Haiku の五つの段階と同じ（形の崩れの問い直しも同じ回数）。
3. 入力のトークン数：Haiku の入力 × 1.3（指示された前提。トークンの数え方の違い）。
4. 推論のトークン数：Haiku の推論（thinking_tokens）× 0.2096。
   - 0.2096 ＝ Sonnet medium 267.75 ÷ Haiku 1,277.25。理解検査（組 1・世界 2・16 例・16 問）の一問あたりの thinking_tokens の平均で、Haiku は予算 2,048、Sonnet は adaptive・effort medium。
   - この比は、それぞれの模型の数え方のトークン数どうしの比なので、3 の 1.3 は掛けない。
   - ★ この比は理解検査（短い履歴・16 例）のもの。本番の段階（40〜80 場面の履歴、予算 8,000 の Haiku との比べ）では違いうる。
5. 本文のトークン数：Haiku の本文 × 1.3。
6. 費用の帳簿の値段の当て方（入力と出力を別に掛けて足す）は、これまでと同じ。キャッシュや一括の割引は使わない。

## 2. 版の固定

- 公式の文書の二つの頁で確かめた（10-02 16:1x に読んだ）。
  - 模型の一覧の頁：https://platform.claude.com/docs/en/about-claude/models/overview（https://platform.claude.com/docs/en/models/overview に転送される）
  - 模型の名前と版の頁：https://platform.claude.com/docs/en/about-claude/models/model-ids-and-versions
- 模型の名前と版の頁の書きぶり（原文の一部）：
  - 「Each Claude model ID identifies a pinned version of the model. When you use a model ID in an API request, the underlying model remains constant for the lifetime of that ID.」
  - 4.6 の世代以降の、日付の無い ID について：「It maps to a single, fixed model snapshot. Anthropic does not update the weights or configuration of an existing model ID. When an updated version is available, it ships under a new model ID.」
  - ただし：「Model weights are fixed for a given ID, but the serving infrastructure around the model can change over time.」とある。要求の振り分け・安全の分類器・標本の取り方など、模型の周りの仕組みが変わると、同じ ID でも振る舞いに小さな違いが出うる、とも書かれている。
- 模型の一覧の頁の表と注：
  - claude-sonnet-5-5・claude-opus-5-5 は、Claude API の ID と別名の欄が同じ文字列。
  - 注に「Every Claude model ID is a pinned snapshot, including the dateless IDs used from the 4.6 generation on.」「Dateless IDs are their own pinned snapshot; the alias row repeats them.」とある。
- 文書の書きぶりでは、claude-sonnet-5-5 と claude-opus-5-5 は、日付は無いがそれ自体が固定版（同じ名前のまま重みと設定は変わらない）。ただし周りの仕組みは変わりうる。
- これまで Haiku で使った claude-haiku-4-5-20251001 は日付つきの固定版。別名 claude-haiku-4-5 は最新の日付つき版を指すもので、私たちは使っていない。

### これまでの LLM の記録に、応答の model の欄が残っているか

- 残っていない。
  - 問いごとの記録（~/llm_trial_out の *.jsonl のうち費用の帳簿以外の 33 ファイル。results の枝の llm_trial/ に上げたものも同じ）のどれにも、応答の model の欄は無い。
  - 記録に書いたのは、使用量（usage）・本文・推論の中身・費用などで、応答の model は書いていない。
- 費用の帳簿（費用.jsonl）の model の欄は、こちらが頼んだ模型の名前（llm_trial/api.py:55 の _book に渡した名前）で、応答の欄ではない。
  - 帳簿の内訳：claude-haiku-4-5-20251001 が 1,511 回、claude-sonnet-5-5 が 48 回、Qwen/Qwen3.5-9B が 129 回、meta-llama/Llama-3.3-70B-Instruct-Turbo が 94 回、Qwen/Qwen3.8-2.4T-A95B が 75 回。
- 応答の model を残すには、llm_trial/api.py で応答の model の欄を記録に書く直しが要る。まだしていない（指示を待つ）。
