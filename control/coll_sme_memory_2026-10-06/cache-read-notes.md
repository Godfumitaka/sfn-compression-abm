# 控えを捨てる案が集団化へ届く所（読むだけ）

版29b89df。変更なし。委任書13番の段2-2を、公開された2026-10-06の委任書20番が具体化している。

- sme2017.Matcher.cache（200、230–249行）: 版・設定・左右の図のfingerprint・同点規則・呼出し種を鍵とし、全Result（仮説・候補・第一位・抽選記録）を持つ。各個体のプロセスに一つずつある。
- smeshared.RESULTS（172–184、222–227行）: 同じmatch_keyを鍵とし、利用側のMappingResultと不変Alignment・auditを持つ。cacheと別の入れ物であり、両方を対象にできれば個体ごとの大きな保持量へ届く。
- Matcher.cache_rng（202、242–249行）、self_cache（201、252–260行）: cacheと関連する開始種／自己点。処分の整合性の検査に含める。
- smeshared.GRAPHS（188行、239–240、345、359行）、CHOICES（245以降、286以降）: 図と同点選択を保持する。RESULTSと一緒に消せるとは未証明。canonical_identity（4096件上限）の控えも別物。
- v311c.choose_partner（192–206行）: 受信Aで逐語すべてと束を比べるたび、通常と同じSMEの控えへ新しい項目が加わり得る。hypo_m1/共通部分/受信後同化にも同じ窓口が使われる。今回q=0では実測しない。
- v311c.probe（503–566行）: 全控えを浅く複製し、指紋を前後に作り、診断後に復元する。安全に保持項目が減れば複製と指紋の時間・一時メモリにも効く可能性がある。
- serial（898–914行）: 一度の重い計算は一個体だが、他の個体のcache/RESULTSはそのプロセスに常駐したまま。共有internが個体間で一つになると仮定しない。

「最後に読まれてから時間がたった」だけでは二度と読まれない証明にならない。集団化では未来の受信・一致試験・cf-value・probe-worldも読む経路になる。退役した名前の再利用や、束の図のfingerprintの再出現がないことまで証明する必要がある。呼出し種はtrialに依存するが、同じtrialの本番と診断・受信にまたがって同じ鍵が使われる場合がある。模型の判断の不変に加え、再利用フラグ・sme_result/sme_use・全side・状態指紋・再生の一致と墓石検査が必要。未来の捨てる旗を試験の保存・復元にも接続し、捨てた鍵を原版から除いた比較の扱いを明示する。今回は削減量を数えず、軽量化を採用しない。

補足：sme2017._Engine.key_cache（272–298行）は一回の照合器の計算に付く控えであり、個体のMatcher.cacheと別。canonicalのsearchのlru_cacheも一回の正準形計算の局所。今回の長期保持の削除案へそのまま混ぜない。smeshared.call_seed（109–115行）には試行番号が入る。古い試行の項目が通常の新しい呼出しの鍵に使われない条件を立てる候補になるが、呼出し全経路・一時復元・受信・試験を含めてSME側の墓石検査で確かめる必要がある。
