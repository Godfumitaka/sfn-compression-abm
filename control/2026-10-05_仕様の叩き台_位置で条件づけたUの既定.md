# 仕様の叩き台：位置で条件づけた U の既定（2026-10-05、Claude）

位置づけ：アストラとの議論用の叩き台。まだ委任書ではない。決めてほしい点は §7。
10/5 午後の改訂：GPT への相談の返事を入れた（住所の曖昧さの扱い、材料の制限、会計）。会計はアストラ了承（数える）。台帳 2026-10-05 午後の R-05k・U-05l・U-05m。
一行で：**U の席は、名前と履歴は忘れるが、形（構造の中の位置）は覚えている。迷ったら「この位置にふつう来る名前」で答える。**

## 1. 今の作りと、その問題

- 席の三つの状態：F（名前と履歴）→ H（履歴だけ）→ U（位置だけ）。覚える量を段々減らす圧縮のはしご（台帳 2026-09-29_30、C-04i、定式化 v0）。
- 今の U の既定の答え（tools/v39.py の u_answer）：個体の全体の語彙の頻度 p̂ のうち、席と同じ形（引数の数、引数が物か関係か、一階か高階か）を持つ名前で一番多いもの。同点なら答えない。席の履歴は読まない。
- 問題：形の絞り込みが粗い。場面の中でその位置に一度も来たことのない名前も候補に入る。
  - お店の世界のドアの席：全場面に出る push・carry・lift が各 100% で同点になり、答えが出ない（台帳 C-05o）。
  - 動詞の世界の過去形の席：同じ理由で答えが出ない。REG（30%）は push・carry・lift（100%）に負ける。
  - 動詞の世界の動詞の名前の席（一引数）：全場面に出る役割の関係 supported が最多になり、既定の答えは supported になる（どの動詞の名前でもない）。
  - お店の世界のシールの席（一引数）：sig_n（約 90%）が supported・carried（各約 50%）より多いので、既定の答えは sig_n（「U の抜け道」、C-03a）。
- つまり、既定の答えが何になるかが「位置の意味」ではなく「世界全体の名前の数の偶然の構成」で決まっている。

## 2. 提案

**U の既定の答えを、位置で条件づけた頻度から選ぶ。** 位置の頻度表は、個体が経験した場面から作る共有の知識（p̂ と同じ扱い）で、席ごとの記憶ではない。

- 原典：Minsky（1975）のフレームの「既定の割り当て」（空所には、具体的な情報が無ければ既定の値が入る）、Rumelhart（1980）のスキーマ。台帳 2026-09-25 にも「既定値は空所の穴埋めに使う」と記録がある。スクリプトの役割の既定（Schank と Abelson 1977）も同じ考え。
- 履歴を忘れることは今と同じ（U は H と区別される）。変わるのは、忘れた後に頼る「全体の知識」が、位置ごとの知識になること。

## 3. 位置の鍵（名前を使わない構造の住所）

案（§7 の Q1）：

1. 場面（又は定義）の中で、ある関係を引数に取る関係を「親」とする。親の無い関係を「上端」とする。場面には上端がふつう複数ある（link の attach、役割の関係、仲立ちなど）。鍵は、各関係が属する木（連結成分）の上端から数える（10/5 夕の明確化）。
2. 位置の鍵＝（上端から自分までの道の各段の（その段の関係の局所の形, 下りる引数の番号）の列, 自分の局所の形）。局所の形＝（引数の数, 各引数が物か関係か）。道の途中の局所の形を入れるのは、別々の木で引数の番号の列だけが同じになる衝突を減らすため（10/5 夕の改訂。下の例は番号の列だけを示す）。
3. 親が複数ある場合（共有された子）は、全部の列を辞書順に並べた組を鍵にする。
4. 名前・ID は使わない。

例（お店の世界・動詞の世界。シールと link が全場面にあるので、上端は link の attach）：

| 関係 | 位置の鍵（引数の番号の列, 局所の形） |
|---|---|
| シール・動詞の名前 | ((0), (1, 物)) |
| ドア・過去形 | ((1,0,0,0), (2, 物物)) |
| ドアの隣の葉（push） | ((1,0,0,1), (2, 物物)) |
| 役割の関係（supported） | ((), (1, 物)) |
| 仲立ち・つなぎ・周縁 | ((), (2, 物物)) ※三つは同じ鍵になる |

- 問われた関係は伏せられていても、親（cause など）がその ID を引数に持つので、場面から位置の鍵を計算できる。
- 定義の席の位置の鍵は、定義の中の関係から同じ手順で計算する。U の席も行（位置）は残っているので計算できる。
- 定義の中で上端までの道が切れている（途中の行が無い）場合は、§5 の代わりの規則。

**鍵が一意に決まらない場合**（初版は、鍵が一意に決まるときだけ使う。決まらなければ §5 に戻して記録する）：

| 場合 | 扱い |
|---|---|
| 一つの関係の祖先が別々の上端に至る | 共有された子で、親の道が別々の木の上端へ行く場合。鍵は全部の道の組（上の 3）。 |
| 同じ場面・定義の中で、同じ鍵の関係が複数ある | 対応づけ（注意の食い違い m）には使わず m＝0 とし、件数を記録する。頻度表には、同じ鍵の関係を全部数える（例：仲立ち・つなぎ・周縁）。 |
| 子を複数の親が共有する | 鍵は全部の道の組（上の 3）。頻度表には一回だけ数え、道の数だけ二重に足さない |
| 定義で祖先が落ちた | 短い鍵へ付け直さない（途中の位置が新しい上端に見えてしまうため）。§5 に戻す。元の鍵を別に控えるなら、その控えも記憶として費用に数える |
| 上に関係が加わる | 中身が同じ役割でも鍵全体が変わる。別の鍵として扱い、合わせない |
| 対称な構造 | 名前・ID なしで位置を区別できないときは §5 に戻す |

## 4. 位置の頻度表

- 内容：位置の鍵ごとに、その位置で見た名前の回数。
- 材料（§7 の Q2）：本人が見た名前と、本人に開示された名前だけ。p̂ と同じ時点で更新する。次の四つを守る。
  1. 自分で補った名前（既定の答えや H の答え）は足さない。
  2. 見えていた関係を、開示の後にもう一度数えない。
  3. 今の試行の正解を、今の予測の前の表に入れない。
  4. 開示されなかった伏せた名前を、場面を作る側から取らない。
- 記憶の費用（§7 の Q3、**決定：数える**）：p̂ は G(p̂) として記憶の総量に入っている（定式化 v0 §3。旧版のこの欄の「p̂ と同じく数えない」は誤り、R-05k）。位置の頻度表も同じ形の G で一回分数える：C_total ＝ C_定義 ＋ G(p̂) ＋ G(位置の表)。全定義で共有するので、定義ごとには数えない。席の判断は費用の差で決まるので、振る舞いは変わらない見込み（総量そのものを使う所が無いかを関門で確かめる）。総量の比べを公平にするため。
- 既定の答え：その席の位置の鍵の表で一番多い名前。同点なら答えない（今と同じ）。今と同じく、一階か高階かの絞り込みも残す。

## 5. 代わりの規則（位置の鍵が使えないとき）

- 席の位置の鍵が計算できない、又はその鍵の表が空のときは、今の u_answer（全体の頻度×形の絞り込み）に戻る（§7 の Q4）。
- 戻った回数を記録する。

## 6. どこが変わるか

u_answer は二か所で使われているので、両方が変わる（これが狙い）。

1. U の席が問われたときの答え。
2. 保持の価値の計算での R_U（U に落とした場合の当たり）。誕生の初期の成績（_init_rec）と、その後の変換（_candidates）の両方。

H の答えの式（席の相対頻度^λ × p̂）の p̂ を位置の表に替えるかは別の問い（§7 の Q5）。一度に一つ変えるため、初版では替えない。このとき H と U は違う統計を参照する比べの条件になることを明記する。

**腕L との連動**：腕L（--score-logp）の確率は P_H＝(1−ε)q_H＋ε·b、P_U＝b で、b は U の既定の分布（台帳 C-05y）。位置の既定を入れると b も位置の分布になり、腕L の値が変わる。両方を採るなら同じ b を使う（U-04j の「分布で一貫させる」）。片方だけ先に主に入れるなら、もう片方を入れるときに走らせ直す。名前の符号の長さ ℓ(p)＝⌈−log₂ p̂(p)⌉（席の費用と、外れの書き直しの費用に使う）も全体の p̂ のまま。位置の表から −log q(p) で測るのが記述の長さとしては筋だが、全部の席の費用が変わるので今回は替えない。

## 7. 決めてほしい点

- **Q1 位置の鍵**：§3 の「上端からの引数の番号の列＋局所の形」でよいか。ALCOVE 型の注意の「列」も同じ鍵にするか（同じにすれば模型がすっきりする）。
- **Q2 頻度表の材料**：見えている関係と開示された関係だけでよいか（記憶の定義から作る案もある）。
- **Q3 記憶の費用**：決定（10/5、アストラ）。G(p̂) と同じ形で数える。
- **Q4 代わりの規則**：鍵が使えないときは今の規則に戻る、でよいか（黙る案もある）。
- **Q5 H への適用**：初版では H の式を替えない、でよいか。
- **Q6 範囲**：まず旧い照合の版の動詞の世界で比べの腕として下見し、次にお店の世界、主に入れるかは 10 月 8 日に決める、でよいか。

## 8. 関門（作るとき）

採否の条件（10 月 8 日）：正解率が上がるかではなく、下の関門・材料の制限・会計が通ること。

1. 旗を切れば、今の版と台帳本体・side が全バイト一致する。
2. 小例：お店と動詞の各世界で、ドア・過去形・シール・動詞の名前・役割の関係・つなぎの位置の鍵と既定の答えが §3 の表どおり。同点・表が空・道が切れた場合の扱い。
3. 位置の鍵が、同じ関係について場面側と定義側で一致する（対応づけた全組で検査）。
4. 頻度表に、開示されなかった伏せた関係の名前が入らない（全試行で検査）。
5. 誕生の初期の成績と変換で、R_U が新しい既定の答えから計算されている（手計算の小例）。
6. 鍵が一意に決まらない場合（§3 の表の五つ）を小例で作り、§5 に戻ること、共有された子を二重に数えないこと、祖先が落ちても短い鍵に付け直さないことを確かめる。鍵は名前・ID に依らない。
7. 材料の四つの決まり（§4）を全試行で検査する。
8. 記憶の総量に G(位置の表) が入り、席の判断が旗の有無で費用の差の分しか変わらないこと（総量そのものを使う所が無いこと）を確かめる。
9. 動詞の世界の過去形の位置で、表の一番が REG かを決まった時点ごとに記録する（設計の差は 4.2 ポイントで、学びの初めは IRR_1 が上になりうる）。

## 9. 結果を見る前の予想（叩き台。確定時に台帳へ）

- 動詞の世界：過去形の席の既定の答えが REG になる（学びの初めは IRR_1 の場合がある）。過去形の席が U の定義から REG の答えが出て、過剰な規則化が増え、黙りが減る。増え方はまれな不規則動詞で大きい。
- 動詞の世界：動詞の名前の席の既定の答えが、最も多い動詞（V33）の名前になる。V33 の定義では、名前を持っても既定の答えと同じなので、生まれたときに名前が U に落ちうる（抜け道が動詞の名前に移る）。名前を失った V33 の定義（答えは IRR_1）は他の動詞にも当てはまるようになり、他の動詞に IRR_1 で答える誤りが増えうる。
- お店の世界：ドアの席の既定の答えは hold と hold_b がほぼ半々で、答えが出るかは偏りしだい。シールの既定の答えは sig_n のままで、抜け道は残る。選び間違いの数は大きくは変わらない。
- どちらの世界でも、既定の答えが位置の意味を持つので、「既定あり（スキーマで再構成）」と「黙る（欠けを自覚）」の差が、答えの席でも現れるようになる。

## 10. 計算と作業の見込み

- 計算：位置の鍵は場面ごとに一度、定義の席ごとに一度。表の更新は p̂ と同じ回数。照合（SME）は呼ばない。増える時間は小さい見込み。
- 作業：旧い照合の版で、実装・関門に半日〜1 日。動詞の世界の下見（A/C/D × 種 1〜5、5,000 試行）は数時間。
