## 前提：この世界で一つの物の組に何本の一階の関係が乗るか（コードで確かめた事実）

- **型の骨組みの一階の関係は、どれも (a,b) の上にある。**
  - abm/world.py:222-226 で `args(("a","b")) if children is None`。
  - 種 seeds/U-011_seed_v3a2.json では、どの型も部分木 2 つ × 下の部分木 2 つ × 一階 2 本で、8 本になる。述語は型の中で重ならない。
- **糊の関係（1〜3 本）は、物 4 つの中から順序つきの組を乱数で選ぶ**（abm/world.py:248-252）。
  - (a,b) に落ちることがある。
  - 糊の名が同じ組に二度落ちることもありうる（まれ）。
- **定義に入る行は構造の行だけ。**
  - 構造の行は、高階の行と、高階の行に引数として参照される行（abm/abstraction.py:81-85, :289-303）。
  - 糊・仲介・周縁・役割ユナリーは入らない。
  - よって、一つの定義の一階の行は、どれも生まれた場面の同じ (a₀,b₀) の上にある。
  - 同化では行を足さない（v31 extend_rule none）。
  - どれか一本の一階の行が写ると、その定義の一階の行すべての写した位置が、同じ (a,b) になる。
- **高階の行の引数は子の関係 ID で、組は関係ごとに一意。**
- **伏せ辺の候補は、一階の構造の関係・仲介・周縁・糊だけ**（abm/world.py:237-254）。高階は伏せない。

### v310be.py:59-61 の採点の詳細

- 開示 q が (a,b) の上の一階の関係のとき、R_used の一階の F・H 席は、どれも位置が (a,b) なので「写した位置が開示の引数と同じ」とされ、採点される。
  - q の席のほかの席（7 本前後）では、次のようになる。
    - 固定名は q と違うので、r_F＝ℓ(q) になる。
    - r_H と r_U は、H・U の答えが q かどうかで決まる。
  - 席の B の記録（R_F・R_H・R_U）は、その席自身の関係ではなく「(a,b) で伏せられた関係」で付く。
- 開示が (a,b) に落ちた糊のときも、同じく一階の席すべてが採点される。
- 開示が仲介・周縁・ほかの組の糊のときは、どの一階の席とも位置が合わず、採点されない。
- 高階の席は、位置が子の ID の組になる。伏せ辺は一階だけなので、採点されることは無い（組の同定としては壊れていない）。

## C　定義の中に親の無い一階の行ができる経路（コードを読んだだけ。数は走行で数える）

### 「親」の読み方

- 構造で読む：同じ定義の行（状態 F・H・U を問わない）で、引数にその行の関係 ID を持つもの。
- この世界の場面では、一階の関係に親は一つだけ（木）。定義の行は一つの土台の場面から来るので、一階の行の親は多くて一つ。
- 行は定義から消えない。
  - 同化で足さない（extend none）。
  - v39 は行を消さず、F→H→U と状態を変えるだけ。θ′ の削除も使わない。
  - 退役は定義ごと消す。
  - よって「構造として親が無い」ことは、誕生のときに決まり、後で変わらない。
- 後で変わるのは「親が居ても写らない」こと。
  - 親が U になると v39_graph に置かれない（v39.py:273-274）ので、どの照合でも写らない。
  - 親が H なら、履歴の名（高階の席の履歴は位置が一意なので、ほぼ親自身の名）で写りうる。

### 経路

1. **今の場面で伏せられた子の兄弟**（誕生）
   - 今の場面の伏せ辺が一階の子 c のとき、土台の親 P は相手の親と対になる。c は相手の側で見えていない枠と対になる（sme.py:298-304）。
   - 組（v39.py:724-731 _pool_pairs＝abstraction.py:76-85 の写し）は `r in target_by_id` を求めるので、c は組に入らない。
   - _drop_childless（v39.py:734-742）が、子が組に無い P を外す。さらに上の親も連鎖して外す。
   - c の兄弟（見えている一階の行）は外されない（_drop_childless は、子の欠けた高階の行だけを外し、親の欠けた一階の行は外さない）。
   - → 親の無い一階の行になる。
2. **土台（逐語の枚）で伏せられ開示されなかった子の兄弟**（誕生）
   - 土台の場面は、その試行の見えている部分と、開示があればその辺だけでできている（agent_runtime.py:394-414、loop.py:89-90）。
   - 開示の無かった試行の枚では、P の引数に子の ID が残るが、その関係は枚に無い。
     - 基の側でその引数は「関係でない」（base_relation_ids に無い）。
     - 相手の側では見えている関係なので、P は対にならない（sme.py:305-307 の食い違い）。
   - P が組に無いので、兄弟の一階の行だけが組に入る → 親の無い一階の行になる。
   - P の上の親も、子（P）が基にあり組に無いので _drop_childless で外れる。
   - 付記：相手の側でも同じ位置が伏せられていれば、P は物の対として組に入る。定義には、子の ID を物として持つ高階の行が残る（まれ）。
3. **写しの採り方で親の対が採られない**（誕生）
   - fixorder2 の同じ鍵の組の中の食い違いで、共通でない候補を採らない（fixorder2.py:152-181）。
   - _candidate_fits で先に採った対と食い違う（sme.py の _candidate_fits）。
   - このとき子の対だけが採られると、兄弟・子の一階の行は親なしで組に入る。
   - この世界で親と子の述語は一対一（部分木 A〜H ごとに一階の名が別）なので、述語の違いで親だけが外れることは無い。
4. **E の誕生**：v310be の新しい定義も、同じ v39.m1 の前処理（_pool_pairs → _drop_childless、v310be.py:175-180 と v39.py:1024-1033）を通るので、1〜3 と同じ。
5. **同化**：経路にならない。
   - extend_rule none で、行を足さない（v31.py:123-125）。
   - 同化の登録は abstraction.py:99-100 → _extend_none が old をそのまま返す。
6. **v39 の変換・退役・逐語の削除**：経路にならない。
   - F→H・H→U は行を残す（v39.py:826-843）。
   - 退役は定義ごと消す（:845-857）。
   - 逐語の削除は原型の枚だけを消す（:1080-1091）。
   - θ′ の行の削除（abm/deletion.py）は、v39 の apply に差し替わって使われない。
   - 変わるのは親の状態だけ（上の「読み方」）。
7. **糊・仲介・周縁・役割ユナリー**：構造の行でないので、定義に入らない（abstraction.py:289-303）。親の無い一階の行の出どころにはならない。
