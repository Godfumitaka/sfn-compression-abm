# クラウド（AWS）の準備：アストラにお願いすること

書いた人：Claude（2026-10-08、アストラの依頼）。所要：**30〜45 分**。

## 全体の形（先に読む）

- AWS の計算機（EC2）で模型を走らせます。動かすのは**デスクトップの走行の係**です（WSL から AWS の操作の道具で、機械を立てる・走らせる・止める）。
- アストラにお願いするのは、**係が使う「鍵」を作って、デスクトップに入れる**ところまでです。機械を立てるのは係が行います。
- お金の安全のために、三つの枠を付けます。
  1. 使える機械の種類と地域を、鍵の権限で絞る（高い機械は立てられない）。
  2. 予算の知らせ（100 ドル）。
  3. 係は、使い終わった機械をすぐ消し、見回りのたびに走っている機械の数を報告する。
- 鍵（アクセスキー）は、**会話（Claude）にも GitHub にも貼らない**でください。デスクトップの WSL の中にだけ置きます。

---

## 手順 1：地域を選ぶ（1 分）

1. AWS のコンソールにログインする。
2. 右上の地域を **「米国東部（バージニア北部）us-east-1」** にする。以下、全部この地域で行います（東京より約 2 割安い）。

## 手順 2：使える芯の上限を確かめる（5 分）

1. 上の検索窓で **「Service Quotas」** を開く。
2. 「AWS のサービス」→ **「Amazon Elastic Compute Cloud (Amazon EC2)」** を開く。
3. 検索窓で次の二つを探し、「適用されたクォータ値」（単位は vCPU）を見る。
   - **Running On-Demand Standard (A, C, D, H, I, M, R, T, Z) instances**
   - **All Standard (A, C, D, H, I, M, R, T, Z) Spot Instance Requests**
4. どちらかが **192 未満**なら、その行を選んで **「アカウントレベルでの引き上げをリクエスト」** → 新しい値に **192** と入れて送る。
   - 理由を聞かれたら：「研究用の CPU のバッチ計算。2〜3 日だけ使う」で十分です。
   - 申請は無料です。通るまで数分〜数日かかります。通るまでの間は、今の上限の中で始めます（較正の走らせ直しは 8〜16 vCPU あれば足ります）。
5. 今の二つの値を、Claude に教えてください（数字だけ）。
   - 二つは別々の枠なので、**32 と 32 なら、合わせて 64 芯**まで同時に使えます（オンデマンド 32＋スポット 32）。その場合は 32 芯の機械（8xlarge）を使います。
   - 32 のままでも、お店の世界（較正の走らせ直し・第 1 波・確認用の種）は 10/10 に間に合う見込みです。動詞と集団化 8 体まで間に合わせるには、引き上げ（192）が通る必要があります。

## 手順 3：予算の知らせ（5 分）

1. 検索窓で **「Billing and Cost Management」** を開く → 左の **「予算（Budgets）」** → **「予算を作成」**。
2. **「テンプレートを使用（シンプル）」** → **「月次コスト予算」** を選ぶ。
3. 予算額に **100（USD）**、知らせを受けるメールアドレスを入れて作成。
   - 実際の額が 85%・100%、見込みが 100% を超えると、メールが届きます。
   - これは知らせだけで、自動では止まりません。止め方は最後の「困ったとき」にあります。

## 手順 4：結果の置き場（S3）を作る（3 分）

1. 検索窓で **「S3」** を開く → **「バケットを作成」**。
2. 名前：**`sfn-abm-results-` ＋ 好きな英小文字と数字**（例：`sfn-abm-results-astra1008`）。世界中で重ならない名前が要ります。
3. 地域が us-east-1 になっていることを確かめる。**ほかの選択肢は、全部初期のままで作成**してよいです。
   - バケットタイプ：汎用（初期のまま）
   - オブジェクト所有者：ACL 無効（初期のまま）
   - パブリックアクセスをすべてブロック：入れたまま（初期のまま。外さない）
   - バージョニング：無効（初期のまま。有効にすると古い写しの分も料金がかかる）
   - タグ：無し
   - 暗号化：SSE-S3・バケットキー有効（初期のまま）
   - オブジェクトロック：無効（初期のまま）
4. 決めた名前を Claude に教えてください。

## 手順 5：係が使う鍵（IAM ユーザー）を作る（10〜15 分）

1. 検索窓で **「IAM」** を開く → 左の **「ユーザー」** → **「ユーザーの作成」**。
2. 名前：**`sfn-runner`**。「コンソールへのアクセス」は**付けない**。→ 次へ。
3. 「ポリシーを直接アタッチする」→ **`AmazonEC2FullAccess`** にチェック → 次へ → 作成。
4. 作った `sfn-runner` を開く → 「許可」→ **「許可を追加」→「インラインポリシーを作成」** → **「JSON」** を選び、中身を全部消して下を貼る。名前は `sfn-limits`。
   - `ここにバケット名` の 2 か所を、手順 4 の名前に書き換えてください。

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "DenyOtherInstanceTypes",
      "Effect": "Deny",
      "Action": "ec2:RunInstances",
      "Resource": "arn:aws:ec2:*:*:instance/*",
      "Condition": {
        "StringNotEquals": {
          "ec2:InstanceType": ["c7a.xlarge", "c7a.8xlarge", "m7a.8xlarge", "r7a.8xlarge", "c7a.16xlarge", "m7a.16xlarge", "r7a.16xlarge"]
        }
      }
    },
    {
      "Sid": "DenyOtherRegions",
      "Effect": "Deny",
      "Action": "ec2:*",
      "Resource": "*",
      "Condition": {
        "StringNotEquals": { "aws:RequestedRegion": "us-east-1" }
      }
    },
    {
      "Sid": "ResultsBucketList",
      "Effect": "Allow",
      "Action": ["s3:ListBucket"],
      "Resource": "arn:aws:s3:::ここにバケット名"
    },
    {
      "Sid": "ResultsBucketObjects",
      "Effect": "Allow",
      "Action": ["s3:GetObject", "s3:PutObject"],
      "Resource": "arn:aws:s3:::ここにバケット名/*"
    }
  ]
}
```

   - これで、立てられる機械は 7 種類（試し用の小さい c7a.xlarge と、32 芯・64 芯の c7a・m7a・r7a）に限られ、地域も us-east-1 だけになります。S3 は、このバケットにだけ読み書きできます（消す権限はありません）。
5. 同じ `sfn-runner` の **「セキュリティ認証情報」** → **「アクセスキーを作成」** → 用途は **「コマンドラインインターフェイス（CLI）」** → 確認にチェック → 作成。
6. **「.csv ファイルをダウンロード」** を押す（アクセスキー ID とシークレットが入っています。この画面を閉じると、シークレットは二度と表示されません）。

## 手順 6：デスクトップに鍵を入れる（5 分）

AWS の操作の道具（AWS CLI）は、先にデスクトップの係に入れさせておきます。アストラは鍵を入れるだけです。

1. デスクトップで WSL の端末を開き、次を打つ。

```
aws configure
```

2. 聞かれる順に入れる。
   - `AWS Access Key ID`：csv の Access key ID
   - `AWS Secret Access Key`：csv の Secret access key
   - `Default region name`：`us-east-1`
   - `Default output format`：`json`
3. 確かめ：次を打ち、`"Arn": "arn:aws:iam::…:user/sfn-runner"` が出れば成功です。

```
aws sts get-caller-identity
```

4. ダウンロードした csv は、パスワードの管理の道具などに控えたうえで、ダウンロードの場所から消してください。

## 手順 7：Claude に知らせる

会話で次の 3 つを教えてください（鍵そのものは書かないでください）。
- 手順 2 の二つの上限の数字（と、引き上げを申請したか）
- 手順 4 のバケット名
- 「aws sts get-caller-identity が通った」

そのあと、Claude が係に指示して、次の順で進めます。アストラの手はもう要りません。
1. 係が、機械に入るための SSH の鍵と、デスクトップの IP だけから入れる入口を作る。
2. 小さい試しの機械（c7a.xlarge）を一台立て、デスクトップの走行と **200 試行で全バイト一致**することを確かめる。
3. 遅い較正の本の走らせ直し（約 5 ドル）→ 第 1 波 → 確認用の種 → 動詞・集団化 8 体の順に、64 芯の機械で走らせる。基本はスポット（安い借り方）。止められたら、その本だけやり直す。
4. 出力は S3 に置いたままにし、表と sha256 と小さい記録だけを GitHub に上げる。
5. 使い終わった機械はすぐ消す。見回りのたびに、走っている機械の数と、その時点の費用を報告する。

## 費用の見込み（全部の計画で）

- スポット中心なら約 70〜110 ドル、オンデマンドなら約 150〜250 ドル。予算の知らせ（100 ドル）に近づいたら、確認用の走行を「主張の候補だけ」に絞って調整します。
- S3 の置き場は、300GB で月 7 ドルほど。終わったら消せば、それ以上かかりません。

## 困ったとき（止め方）

- **今すぐ全部止めたい**：コンソールで地域が us-east-1 になっているのを確かめ、**EC2 → インスタンス → 全部にチェック → 「インスタンスの状態」→「終了」**。S3 の結果は残ります。
- **鍵を無効にしたい**：IAM → ユーザー → `sfn-runner` → セキュリティ認証情報 → アクセスキーを「無効化」。係は何もできなくなります。
- **料金を見たい**：Billing and Cost Management → 「コストエクスプローラー」又は「請求書」。
