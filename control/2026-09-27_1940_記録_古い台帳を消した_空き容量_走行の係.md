## C ドライブの空き：29 GB（消す前と同じ）
- Ubuntu の中のファイルは、C ドライブ上の仮想ディスク一つ（ext4.vhdx）に入っている。WSL の既定では、中でファイルを消しても、この仮想ディスクは小さくならない。そのため C ドライブの空きは増えなかった。
  - 仮想ディスクの大きさ：69 GB。
  - Ubuntu の中で実際に使っている量：41 GB。
  - 差の約 28 GB（今回消した約 23 GB を含む）は、Ubuntu の中では再び使えるが、C ドライブには返っていない。
  - この PC には .wslconfig が無く、自動で返す設定（sparse）は入っていない。
- 本番の台本は C ドライブの空き（/mnt/c）を見て、20 GB を切ると新しい走行を待つ。
  - 今の空き 29 GB から見て、v3.6 の並びの途中で待ちに入る見込みは変わらない。
  - 中で再び使える空きがあるので、仮想ディスクがそれ以上大きくならずに済む可能性はある。ただし、ext4 が消した場所を使い直すとは限らない。

## 空きを C ドライブに返すには（どれも私の側ではしていない）
- 仮想ディスクを小さくするには、WSL を止める必要がある。止めると本番の走行も止まる。
  - 例：Windows の PowerShell で `wsl --shutdown` のあと、`wsl --manage Ubuntu-24.04 --set-sparse true`（以後は自動で返す）。
  - または、管理者の PowerShell で `Optimize-VHD`、あるいは diskpart の `compact vdisk`。
  - 走行は、止めてから台本をもう一度走らせれば、終わった台帳を飛ばして続きから進む。
- WSL を止めない別の手：台本の下限を下げる（`MINFREE_GB=10` などで走らせ直す。終わった台帳は飛ばす）。
  - C ドライブの空きがそれだけ減ってよいかは、Windows 側の都合による。
- どれにするか（何もしないを含む）は、control/ に書いてください。何も書かれなければ、今のまま続け、待ちに入ったらまた書きます。
